## Implementation and security claims inspected

- `vision.py`: multithreshold Canny contours, convex-quadrilateral and lighter-paper support filters; fallback bright-region heuristic; Laplacian-detail and bright-region checks. These are geometric/intensity heuristics, not OCR or semantic completeness checks.
- `page_crop.py` / `recovery.py`: best-effort partial visible-edge or bright-region crops, explicit uncertainty warnings, original retained, natural/contrast/black-white alternatives. Recovery proposals capped to a 1200-pixel long side without upsampling; aligned-document preview has a separate 1600-pixel cap. No generative restoration.
- `rectify.py`: finite normalized four-corner validation, convexity, minimum edge/area checks and perspective warp. Human-selected borders do not certify document completeness.
- `web/app.js`: excluded-area overlay, crop undo, manual edits and rotation; changes revoke acceptance. Packaging checks current request, variant, rotation and approval object before download. SHA-256 binds reviewed JPEG bytes to the JSON record; no signer identity or authenticity guarantee. Separate automatic check-record exports and explicitly human-reviewed exports retain their distinct meanings.
- `server.py`: loopback binding, Host/Origin checks and no request-payload logging. Local dispatch bypasses cloud-specific credential/allowance controls intentionally; do not expose this development server to a network.
- `service.py`, `judge_auth.py`, `public_guard.py`: cloud auth before analysis; expiry and missing-configuration failures; atomic DynamoDB attempt consumption when configured. DynamoDB stores an allowance counter, not document content. Application code does not persist source images; this is not an audited infrastructure privacy/compliance guarantee.
